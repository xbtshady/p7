# p7 架构文档 · 2.0

原生 Android（Java + XML），无 WebView、无网络。题目来自 `assets/bank.json`，进度写在应用目录外。本文是 **2.0 目标架构**；仓库内实现可能仍接近 [1.1 归档](../1.1/架构文档.md)，改造时以本文为准。

## 3. bank.json

```json
{
  "schemaVersion": 1,
  "bankVersion": 8,
  "questions": [
    {
      "id": "L1-T1-0001",
      "type": "truth",
      "level": 1,
      "mode": "answer",
      "prototype": "knights-knaves",
      "prompt": {
        "people": [
          {"name": "杰克逊", "says": "奥利弗撒谎"},
          {"name": "奥利弗", "says": "索菲娅撒谎"}
        ],
        "constraint": "每人的话和他的身份都对得上，只有这一种分法"
      },
      "answer": {
        "truth": {"杰克逊": false, "奥利弗": true},
        "liars": 1
      },
      "solution": {
        "lines": ["…"],
        "summary": "…"
      }
    }
  ]
}
```

### 3.1 字段

| 字段 | 约定 |
| --- | --- |
| `type` | 现行产品只消费 `truth`。`ledger` 若出现：校验可保留，UI 不展示、抽题池可排除 |
| `mode` | 仅实现 `answer`；读到其它 mode 跳过 |
| `level` | 1..5 |
| `prototype` | 可选；app 不解析 |
| `answer.truth` | 判题唯一依据（键与 people 名一致） |
| `answer.liars` | 数据可保留；**玩家不填**；可选用于生成后自检 |
| `solution` | `lines` + `summary`，提交后「推演」用 |

- **数组顺序** = 题库页在同一筛选下的稳定顺序。  
- **禁止改已发布 id**；增题追加；改内容换新 id。  
- 题库内禁止 UI 文案、颜色、卡点选项。

### 3.2 加载与规模

- 现行约 1.2 万题、数十 MB：启动仍可一次读入（设备允许时）；若 OOM，再改为按 level 分文件或流式索引（预留，本版不强制）。
- 不引 Gson/Jackson；`org.json` 手取字段。
- 坏题：丢弃 + 日志，不抛死；全灭 → 概览提示题库异常。

### 3.3 校验（truth）

公共：`type` 已知、`mode==answer`、`level∈1..5`、`id` 非空唯一。  
truth：`people` 非空且含 name/says；`constraint` 非空；`answer.truth` 键与人名一致；`solution.lines` 非空。`liars` 若存在须为整数且与 truth 中 false 个数一致（不一致则丢弃或打日志后纠正策略二选一，实现选定后写死）。

## 5. progress.json

```json
{
  "schemaVersion": 1,
  "bankVersion": 8,
  "auxTier": "standard",
  "lastQid": "L2-T1-0183",
  "filterLevel": 2,
  "filterStatus": "all",
  "records": [
    {
      "qid": "L2-T1-0183",
      "ts": 1761111111111,
      "ok": true,
      "ms": 108000,
      "aux": "standard",
      "stuck": null
    }
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| `auxTier` | `loose` / `standard` / `challenge` |
| `lastQid` | 避免连续抽同题 |
| `filterLevel` / `filterStatus` | 概览 CTA 与题库默认筛选（`filterStatus`: `all`/`todo`/`tried`/`solved`）；可缺省 |
| `records` | 只增不覆盖；上限建议 ≥5000（大池下可调到 10000，超出丢最旧） |

### 5.1 派生（不落盘）

| 派生 | 算法 |
| --- | --- |
| 题状态 | 无记录 → 未做；有记录且无 ok → 尝试；任一条 ok → 已对 |
| 某级已对数 | 该级题中状态为已对的个数 |
| 首次结果 | 该 qid **最早**一条的 `ok`（统计首次正确率用） |
| 首次正确率 | 近 N 个「各题首次记录」中 ok 比例（按时间取最近涉及的题的首次提交） |

1.x 的「列表展示首次对/错」「首页已做题号去重/总量」不再作为 UI 主口径。

## 6. ProgressStore

- 路径：`getExternalMediaDirs()[0]/p7/progress.json`  
- 降级：`getFilesDir()` + `volatileOnly`  
- 原子写：tmp + rename；坏文件备份 `progress.bad.json`  
- 迁移：`schemaVersion` 逐版升级；`bankVersion` 变化时过滤不存在的 qid，保留 `auxTier` 与筛选字段  

## 7. 抽题 Picker

输入：筛选后的 id 列表（或 Question 列表）、`lastQid`。

```
pool = 筛选结果且 mode=answer 且 type=truth（产品池）
若 size>1 且含 lastQid → 去掉 lastQid
等概率随机
空 → EMPTY
```

概览 CTA、题库「随机」、题目页「下一题」共用；筛选来源分别为概览默认 / 题库当前 / 进入题目页时锁定的筛选快照。

## 8. 判定 Grader

| 题型 | 条件 |
| --- | --- |
| truth | 玩家每人真假与 `answer.truth` 全等。不要求玩家提交 liars；若 UI 未选某人则 `partial` |

`signal`：`partial` / `timeout` /（可选）`allSame`——写日志，可写入分析，不驱动 UI 文案。

### 8.1 写记录时机

| 触发 | ok | ms |
| --- | --- | --- |
| 提交 | 判题结果 | 实际用时 |
| 挑战超时 | false | 该级时限毫秒 |

不写：关闭题目页、返回、杀进程。

超时：界面锁定已填内容；可重做；卡点可回写该条 `stuck`。

## 9. 页面与状态

```
启动 → load bank + progress
     → 底栏：OVERVIEW | BANK | HISTORY
     → QUESTION（全屏，携带来源与筛选快照）
```

| 页 | 职责 |
| --- | --- |
| OVERVIEW | 统计聚合、CTA、最近提交、设置入口 |
| BANK | 筛选、分页、随机、点题 |
| HISTORY | 提交时间线、点题 |
| QUESTION | 作答闭环 |

BankRepo 需支持：`ofLevel`、`byId`、`page(filter, offset, limit)`、`count(filter)`、`idsMatching(filter)`。

## 12. 风险与未定

| 项 | 说明 |
| --- | --- |
| 大 JSON 启动耗时 / 内存 | 需真机测；不行再拆包 |
| 看过推演后重做 | 统计靠首次正确率稀释；不做防作弊 |
| `Android/media` 卸载策略 | ROM 差异；丢档再考虑 SAF |
| ledger 死代码 | 可暂留 Renderer，勿挂导航 |
| release 签名 | 未做 |

## 13. 相对 1.1 架构要点

- 三页（家/列表/题）→ 四页 + 底栏  
- 全量一级 ListView → 筛选分页  
- 进度口径：已做去重 → 已对/尝试 + 首次率  
- Grader：双条件（truth+liars 输入）→ 仅 truth 映射  
- 标准/挑战旧交互（藏题面、第一步）删除  
- 文档迁入 `docs/{version}/`
