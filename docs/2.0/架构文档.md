## 3. bank.json

字段约定见既有 truth 协议。`answer.truth` 为判题依据；`answer.liars` 可保留供自检，**玩家不填**。

### 3.1 加载

约 1.2 万题、数十 MB：启动一次读入；OOM 再拆包。坏题丢弃+日志；全灭→概览异常。

### 3.2 校验（truth）— 唯一策略

公共：`type` 已知、`mode==answer`、`level∈1..5`、`id` 非空唯一。  
truth：`people` 非空且含 name/says；`constraint` 非空；`answer.truth` 键与人名一致；`solution.lines` 非空。

若存在 `liars`：必须为整数且等于 `truth` 中 `false` 的个数。  
**不一致 → 丢弃该题并打错误日志，禁止自动纠正后入库。**

### 3.3 质量门槛（导入侧）

与产品需求 §2.1 对齐：唯一解枚举、与官方解一致、近重复策略、语言抽检、难度抽样、来源许可记录。规模不是通过门槛的替代条件。

### 3.4 难度与时限

- 现行 L1–L5 **启发式以人数为主**，不等于推理负荷；导入脚本可附带人数分布说明。  
- 挑战时限为**初值**（待试测校准）：

| level | 时限 ms |
| --- | --- |
| 1 | 90_000 |
| 2 | 105_000 |
| 3 | 120_000 |
| 4 | 150_000 |
| 5 | 180_000 |

## 5. progress.json

```json
{
  "schemaVersion": 1,
  "bankVersion": 8,
  "auxTier": "standard",
  "lastQid": "L2-T1-0183",
  "filterLevel": 2,
  "filterStatus": "all",
  "records": [
    {
      "qid": "L2-T1-0183",
      "ts": 1761111111111,
      "ok": true,
      "ms": 108000,
      "aux": "standard",
      "stuck": null,
      "bankVersion": 8
    }
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| `auxTier` | loose / standard / challenge |
| `lastQid` | 避开连续同题（见交互设计） |
| `filterLevel` / `filterStatus` | 概览默认筛选 |
| `records` | 只增不覆盖 |

### 5.1 容量与截断

- **硬上限：10000** 条；超出丢最旧。  
- 截断后：所有派生统计（已对、首次正确率、近 7 日）**仅基于仍保留的 records**；首次正确率窗口可能不足 N，按实际条数计算。

### 5.2 派生算法

| 派生 | 算法 |
| --- | --- |
| 题状态 | 无记录→未做；有记录且无 ok→尝试；任一条 ok→已对 |
| 某级已对 | 该级题中已对个数 |
| 某题首次记录 | 该 qid **最早**一条 |
| 首次正确率 | 各题首次记录按 `ts` 降序，取前 N（默认 50），ok 比例；**每题至多一次** |

### 5.3 题库版本与记录语义

| 事件 | 语义 |
| --- | --- |
| 写入提交 | 记录带当时的 `bankVersion` |
| 当前 `bankVersion` 变化 | 过滤 `qid` 已不在新题库中的记录；保留 `auxTier` 与筛选字段 |
| 同 id 内容被替换 | **禁止**；改内容必须换新 id。故旧记录仍解释为「对该 id 的历史 Attempt」 |
| 卸载 | `Android/media/...` 通常保留，**不保证**（ROM 差异）；降级到内部目录则卸载丢失 |
| 写失败 / 空间不足 | 保持内存态；下次启动以磁盘为准；可打日志；不假装已持久化 |
| 文件损坏 | 备份 `progress.bad.json`，新建空进度 |

## 6. ProgressStore

路径：`getExternalMediaDirs()[0]/p7/progress.json`；降级 `getFilesDir()` + `volatileOnly`。原子写 tmp+rename。

## 7. 抽题 Picker

见交互设计：`filterSnapshot` 池内随机，避开 `lastQid`（池>1）。

## 8. 判定 Grader

truth：每人真假与 `answer.truth` 全等；有人未选 → `partial` 且判错。不要求玩家提交 liars。

写记录：提交或挑战超时；关闭/返回/杀进程不写。超时 ms = 该级时限。

## 9. 页面

底栏 OVERVIEW | BANK | HISTORY；QUESTION 全屏。导航回退见交互设计 §6.1。

## 10. 构建与题库发布

```bash
# PC：导入并校验 → 覆盖 app 真源
python bank/import_knights.py   # 以脚本实际参数为准
# 将生成的 bank.json 拷入 app/src/main/assets/bank.json
# 内容变更则递增 bankVersion
cd app && ./gradlew assembleDebug
```
